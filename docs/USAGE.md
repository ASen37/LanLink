# LanLink 使用文档

> 返回 [README](../README.md)

LanLink 是一个纯局域网文件直传工具，提供两种互不依赖的工作方式：

| 方式 | 使用场景 | 对方需要安装吗 | 传输安全 |
| --- | --- | --- | --- |
| 设备互传 | 两台电脑都装了 LanLink | 需要 | 端到端加密（X25519 + AES-256-GCM） |
| 访客网页上传 | 对方只有浏览器（手机、临时电脑、访客） | 不需要 | 邀请链接令牌 + 6 位访问码（HTTP，仅限可信局域网） |

文件不经过任何云端服务器，也没有账号和遥测。桌面端基于 Electron，核心传输是一个零第三方运行时依赖的 Node.js 服务。

---

## 1. 安装与启动

### 环境要求

- Windows 10/11、macOS 或 Linux（当前主要在 Windows 上验证）
- Node.js 20 及以上（推荐 22/24）
- 两台设备处于同一局域网、同一网段

### 安装依赖

```bash
cd lanlink
npm install
```

### 桌面版（推荐）

```bash
npm start
```

会打开 LanLink 桌面窗口，同时在本机启动传输服务。首次运行 Windows 防火墙弹窗时，请勾选“专用网络”并允许访问，否则其他设备无法连接。

桌面窗口内嵌的 Web 界面与传输服务由同一份代码提供，无需也不支持以浏览器方式单独运行；下面 `dev:a` / `dev:b` 启动的浏览器页面仅用于本地联调。

### 同一台电脑跑两个实例（测试用）

```bash
npm run dev:a
npm run dev:b
```

分别打开 `http://127.0.0.1:7421` 与 `http://127.0.0.1:7431`。两个实例使用同一个 UDP 发现端口（7424），数据目录分别为 `dev/node-a`、`dev/node-b`，并开启了自动信任（仅用于本地联调）。

桌面版直接再执行一次 `npm start` 也可以多开：第二次启动会自动改用独立配置目录（`%APPDATA%\lanlink-2`，依次顺延），生成独立设备身份（设备名称自动加序号后缀），两扇窗口通过组播互相发现。每个实例启动时会在自己的配置目录写入 `instance.lock` 记录进程号，退出时删除；进程异常退出留下的锁会在下次启动时自动回收。

### 界面与主题

桌面窗口与访客页都是 8bit 像素风界面（NES.css 组件 + 中文像素字体），右上角的 **亮 / 暗** 可以随时切换配色，选择记在本地（`localStorage` 的 `lanlink-theme`），下次打开保持不变，默认亮色。

桌面端分四个页签：

- **设备**：左侧发送区（拖拽 / 发送文件 / 手动连接）与附近设备列表，右侧本机信息、访客上传与安全说明。
- **传输**：进行中任务的进度、速度、剩余时间与取消按钮。
- **历史**：最近 200 条记录，可定位文件或删除。
- **设置**：本机信息、接收与归档、访客上传、网络与安全模型，底部保存条始终可见。

## 2. 首次启动

启动后 LanLink 会自动生成设备身份：

- **设备 ID**：Ed25519 公钥 SHA-256 的前 20 字节（40 位十六进制）
- **设备指纹**：完整 SHA-256 指纹，用于人工核对身份
- **设备名称**：默认取主机名，可在“设置 → 本机信息”中修改

设备身份保存在数据目录中，删除 `identity.json` 等于换了一台新设备，之前的配对关系全部失效。

### 数据目录位置

| 运行方式 | 默认位置 |
| --- | --- |
| 桌面版（Windows） | `%APPDATA%\lanlink\data` |
| 桌面版（macOS） | `~/Library/Application Support/lanlink/data` |
| 桌面版（Linux） | `~/.config/lanlink/data` |
| 桌面版第二实例 | 同上，目录名追加 `-2`、`-3`… |
| 命令行开发实例（`node src/server.js`） | `~/.lanlink` |

以设置页“程序数据”一栏显示的路径为准，也可点“打开数据目录”。

## 3. 设备互传（双方都安装 LanLink）

### 3.1 发现对方

两台电脑都启动 LanLink 且在同一网段时，“设备”页会自动列出附近设备（UDP 组播，约 2.5 秒广播一次）。

以下情况自动发现会失效，请使用“手动连接 IP”：

- 路由器开启了 AP 隔离 / 访客网络隔离
- 公司网络禁用了组播
- 使用了 VPN、虚拟机或防火墙拦截了 UDP
- 两台机器不在同一网段

手动连接需要填写对方 IP 和 TCP 接收端口（默认 `7411`），可在对方设置页“网络”中查看实际端口。IP 按四段输入，每段 0–255，输满自动跳下一段，也支持整段粘贴。

### 3.2 首次配对

1. 在设备卡片上点“配对”。
2. 双方屏幕都会显示同一个 6 位验证码。
3. 人工核对两边数字一致后，接收方点“验证码一致，接受”。

验证码一致可以排除中间人攻击。配对成功后设备会加入信任列表，之后连接不再需要确认。如果验证码不一致，请拒绝并检查网络环境。

设备卡片上的状态含义：

- **未配对**：可以看到，点“配对”建立信任
- **已配对**：直接点“发送文件”；卡片上的“断开”会同时关闭连接并取消双方的配对（对方也会收到取消通知），断开后两台设备回到“未配对”状态，需要重新配对才能传输；已配对但当前不在线的设备也可点“断开”来解除配对
- **离线**：保留在列表中，点“重连”尝试重新连接

### 3.3 发送文件

三种方式任选：

- 点“发送文件”，选择文件/文件夹
- 把文件或文件夹拖到虚线区域
- 点“快速发送”，先选文件再选接收设备

发送方会先扫描并计算分块哈希（传输页显示“正在准备”），随后把清单发给对方。

接收方会弹出确认框，可修改接收位置后点“接收”。点“选择”会打开页面内的文件夹浏览器（根节点为“此电脑”），也可以直接输入绝对路径。如果接收方开启了“自动接受传输”，且发送方是已配对设备，则不再弹窗，直接写入默认接收目录。

### 3.4 传输与历史

- **传输页**：显示当前任务、总进度、速度、剩余时间、当前文件；可取消任务；完成后可直接打开所在位置（桌面版）。
- **历史页**：保留最近 200 条已完成/失败/取消记录，可查看路径、大小、状态和访客 IP；接收记录点“打开”会在资源管理器/Finder 中定位文件，文件夹记录则直接打开该目录；发送记录点“打开”会定位本地发送的源文件/文件夹；路径已不存在时会提示“文件或文件夹不存在”；每条记录右侧的“删除”可单独移除，右上角“清空记录”会一次清空全部。

传输状态包括：准备中、等待配对、等待对方接收、传输中、收尾、已完成、失败、已取消。

### 3.5 续传、跳过与归档

- **断点续传**：接收方先把数据写入 `<文件名>.lanlink-part`，并在 `.lanlink-part.json` 中记录已完成分块。连接中断后重新发送相同内容会只补传缺失分块。
- **自动跳过**：目标位置已有同名文件，且大小相同、修改时间相差不到 2 秒，或大小相同且树哈希一致时，直接视为已完成，不重复传输。
- **旧版本归档**：覆盖同名文件时，旧文件移动到接收目录下的 `.lanlink-archive/<时间戳>/<相对路径>`。
- **冲突副本**：关闭“保留旧版本归档”后，旧文件改名为 `文件名 (conflict copy 时间).扩展名`，不会被删除。
- **并发同名**：两台设备同时发送同一路径时，接收端会给后到的文件自动加序号（如 `name (2).ext`），两个文件都会保留；访客上传遇到同名文件仍在接收时，会提示稍后重试。
- **分块校验**：每个分块单独做 SHA-256 校验，失败自动重传（最多 4 次），多次失败则任务终止。
- **未完成分块清理**：超过“未完成分块保留时长”的临时数据不再用于续传，下次相同传输会重新开始；设为 0 表示永久保留。

文件夹传输会保留目录结构。以下文件会被忽略：`desktop.ini`、`Thumbs.db`、`.DS_Store`、`$RECYCLE.BIN`、`System Volume Information`、`.lanlink-archive`，以及所有 `.lanlink-part` / `.lanlink-part.json` 临时文件。符号链接不会被跟随。

## 4. 访客网页上传（对方零安装）

访客上传默认关闭，关闭时不会监听任何对外端口。

### 4.1 主机开启

方式一：在“设备”页的“访客网页上传”面板点“开启访客上传”。

方式二：在“设置 → 访客上传”中打开开关。

开启后，面板会显示：

- **邀请链接**：`http://<本机局域网 IP>:<端口>/u/<32 位随机令牌>`（多网卡时会列出多个地址；**192.168.\* 优先作为主链接**，其次是 10.\* / 172.16–31.\*，虚拟网卡整体降权，没有 192.168.\* 时才按原顺序取第一条）
- **6 位访问码**
- **过期时间**

把链接和访问码一起发给对方即可。点“复制链接”“复制访问码”“打开”可快速操作。

> 安全策略：每次开启访客模式都会生成新的链接和访问码；LanLink 每次启动时访客模式默认关闭，旧链接立即失效，需要重新开启才会生成新链接。

同一局域网内，对方用浏览器打开链接，输入访问码后即可：

1. 拖入文件/文件夹，或点“选择文件”“选择文件夹”
2. 确认文件列表，点“开始上传”
3. 查看总进度、速度、剩余时间；可随时取消
4. 上传完成后再点“继续上传”选择下一批

文件列表按目录展示：文件夹显示文件数与总大小，点进去可以继续浏览，列表顶部的 `..` 返回上一级；每个文件右侧的“移除”可以单独剔除。右下角的“+ 添加文件 / 文件夹”可以在已选列表上继续追加。

对方需要保持页面打开。中断后重新选择相同文件即可续传（要求文件大小和修改时间一致，且未超过保留时长）。

### 4.2 文件落在哪里

所有访客文件写入：

```
<默认接收位置>\访客上传\<对方选择的文件夹或文件名>
```

文件夹上传会保留相对目录结构。主机“传输”页和“历史”页会以“访客”徽标显示任务，并附带访客 IP。

同名文件的处理与设备互传一致：默认归档旧版本，关闭归档时生成冲突副本。主机也可以在“传输”页取消正在进行的访客上传，对方页面会立即显示上传已取消。

### 4.3 访客下载文件

在“设置 → 访客上传”里打开 **允许访客下载文件**，再点“选文件夹”或“选文件”指定共享目标（只读）。访客页面顶部会出现「上传文件 / 下载文件」两个页签。

- 下载页按目录浏览，文件右侧的「下载」用浏览器原生下载保存
- 支持 HTTP Range，浏览器可以断点续传
- 只暴露所选文件/文件夹：目录穿越、隐藏文件（以 `.` 开头）、符号链接、其他路径一律拒绝
- 关闭开关或关闭访客模式后立即失效

下载走 HTTP 流式传输，不经过任何中继；千兆局域网通常能跑到 100 MB/s 以上。

> 暂不支持文件夹整体打包下载，需要进入目录后逐个下载。

### 4.4 免验证码模式（可选）

设置 → 网络 → 关闭 **启用验证码校验**，会先弹出风险确认。关闭后：

- **访客模式**：打开链接直接进入上传/下载页，页头显示「免验证码」标记，不再输入 6 位访问码
- **设备配对**：按双方设置分三种情况

| 本机 | 对方 | 行为 |
| --- | --- | --- |
| 关闭 | 开启 | 本机主动配对会被拦截，提示「对方已开启配对验证」，可一键开启验证码后继续；配对请求不会到达对方 |
| 开启 | 关闭 | 按免验证码流程，对方确认即可 |
| 关闭 | 关闭 | 按免验证码流程，对方确认即可 |

> 如果对方主动来配对关闭了验证码的本机，仍然只需本机点一次「允许配对」。

适用场景：完全可信的家庭或小办公室网络、临时演示。

风险：

- 任何拿到访客链接的人都能直接上传，也能下载共享文件
- 同一局域网内的设备可以发起配对，只需有人点一次「允许」
- 首次配对时没有带外验证码，无法用肉眼发现中间人

建议保持开启；确实需要时再用，用完及时恢复，并配合「每次开启换新链接」「链接有效期」使用。访客与 P2P 共用这一个开关。

### 4.5 限制与保护（默认值）

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 监听端口 | 7420 | 被占用时自动尝试 +1 到 +10 |
| 链接有效期 | 12 小时 | 0 表示永久；到期自动关闭访客上传 |
| 单文件上限 | 4096 MB | 可在设置中调整 |
| 单批总量上限 | 20480 MB | 单次选择的所有文件合计 |
| 单批文件数 | 20000 | 服务端硬限制 |
| 同时上传任务 | 全局 12 个 | 每个 IP 最多 3 个 |
| 空闲超时 | 10 分钟 | 无任何活动即终止该批上传 |
| 登录保护 | 每 IP 每分钟 20 次尝试 | 超限后锁定 5 分钟，成功登录会清零 |
| 访客会话 | 12 小时 | 且不超过链接过期时间 |

服务端以 4 MiB 分块接收，逐块做 SHA-256 校验，并支持断点续传；磁盘空间不足会拒绝整批任务。

### 4.6 更新链接、过期与关闭

- **更新链接与访问码**：旧链接、旧访问码立即失效，正在上传的访客任务会被取消。建议每次分享结束后轮换一次。
- **到期**：到达有效期后自动关闭访客上传并提示。
- **手动关闭**：开关关闭后端口停止监听，已打开的访客页面立即失效。

### 4.7 安全说明

访客模式是 HTTP，不是 HTTPS，流量在局域网内没有加密。它依靠随机链接令牌、6 位访问码、HttpOnly + SameSite=Strict Cookie、登录限速和路径约束来限制访问。

因此：

- 仅在可信局域网开启，不要在公共 Wi-Fi、宿舍网、展会网络长期开启
- 不要把链接转发到群聊或公网
- 用完即关，或点“更新链接”使旧链接失效
- 需要强保密时，使用双方都安装 LanLink 的端到端加密模式
- 免验证码模式下，链接本身就是唯一凭证，务必配合短有效期和用后即关

## 5. 设置项说明

### 本机信息

| 设置 | 说明 |
| --- | --- |
| 设备名称 | 显示给其他设备的名称，最长 64 字符，保存后立即生效 |
| 设备指纹 | 只读，用于线下核对身份 |
| 设备 ID | 只读，身份公钥派生 |
| 本机地址 | 当前用于接收连接的地址与端口 |
| 程序数据 | 设置、身份、信任列表、历史的保存目录 |

### 接收与归档

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 默认接收位置 | `下载\LanLink` | 设备互传的默认目录；访客文件写入其下的 `访客上传` |
| 自动接受传输 | 关闭 | 仅对已配对设备生效 |
| 保留旧版本归档 | 开启 | 关闭后改为生成冲突副本 |
| 未完成分块保留时长 | 24 小时 | 0 表示永久保留，便于长期续传 |

### 访客上传

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 开启访客网页上传 | 关闭 | 打开后开始监听 0.0.0.0 |
| 监听端口 | 7420 | 范围 1024–65535 |
| 链接有效期 | 12 小时 | 0 表示永久 |
| 单文件上限 | 4096 MB | 1–1048576 MB |
| 单批上限 | 20480 MB | 1–1048576 MB |

修改端口、有效期等设置并保存后立即生效。仅调整有效期不影响已登录会话；修改监听端口或更新链接会使访客需要重新输入访问码。

### 网络

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 局域网自动发现 | 开启 | 通过 UDP 组播广播设备信息 |
| TCP 接收端口 | 7411 | 被占用时自动 +1 尝试，最多 5 次，仍失败则改用随机端口 |
| UDP 发现端口 | 7412 | 组播组 239.255.42.99，TTL 1，不跨路由器 |

## 6. 端口与防火墙

| 用途 | 默认端口 | 绑定地址 | 何时监听 |
| --- | --- | --- | --- |
| 桌面/联调 GUI（HTTP + SSE） | 桌面版随机；命令行实例 7410 | 127.0.0.1 | 始终 |
| 设备间传输（TCP） | 7411 | 0.0.0.0 | 始终 |
| 局域网发现（UDP 组播） | 7412 | 0.0.0.0 | 开启自动发现时 |
| 访客上传（HTTP） | 7420 | 0.0.0.0 | 仅开启访客上传时 |

Windows 防火墙只需放行“专用网络”。如果希望手动添加规则，至少需要：入站 TCP 7411（及实际显示端口）、入站 UDP 7412、入站 TCP 7420（仅访客模式）。GUI 端口只在本机回环，不需要放行。

跨网段、跨 VLAN、开启 AP 隔离时组播无法通过，请直接使用“手动连接 IP”。

## 7. 性能参考

在同一台机器上通过回环网络传输的实测（512 MB 单文件 + 2000 个 4 KB 小文件）：

| 阶段 | 大文件平均速度 | 2000 个小文件耗时 | 小文件速率 |
| --- | --- | --- | --- |
| 早期版本 | 48.5 MB/s | 32.6 s | 61 个/s |
| 优化后 | 135–156 MB/s | 10–17 s | 116–198 个/s |

访客 HTTP 上传（同一台机器回环，256 MB 单文件，4 MiB 分块）：

| 并发上传请求 | 平均速度 |
| --- | --- |
| 2 | 约 220 MB/s |
| 3 | 约 246 MB/s |
| 4 | 约 250 MB/s |

这说明协议和服务端本身不是瓶颈；真实局域网中的访客上传速度基本等于链路速率：

| 链路 | 理论峰值 | 实际常见值 |
| --- | --- | --- |
| 100 Mbps 以太网 | 12.5 MB/s | 10–11.5 MB/s |
| 千兆以太网 | 125 MB/s | 100–113 MB/s |
| Wi-Fi 2.4 GHz | 150–300 Mbps | 5–8 MB/s |
| Wi-Fi 5 GHz | 433–1200 Mbps | 20–60 MB/s |

如果访客上传稳定在 10 MB/s 左右，优先检查两端网卡协商速率：Windows 可打开“任务管理器 → 性能 → 以太网/Wi-Fi”查看“链接速度”，或运行 `Get-NetAdapter | Select Name, LinkSpeed`；同时确认没有经过百兆交换机/路由器、是否连在 2.4 GHz 频段。

注意：

- 真实局域网受网线与网卡限制：千兆以太网理论上限约 110 MB/s，2.5G/10G 网络才能跑得更高。
- 大量小文件的瓶颈通常在文件系统与杀毒软件实时扫描，而不是加密或协议本身。这台测试机上仅创建/写入/重命名 2000 个 4 KB 文件就需要约 6.4 ms/个。
- 跑分波动较大，与后台程序、Defender 扫描、磁盘缓存状态有关。

提升建议：

1. 优先使用有线网络，关闭 Wi-Fi 节能模式；避免同时进行大文件下载、视频会议或虚拟机磁盘操作。
2. 为接收目录和 LanLink 程序目录添加杀毒软件排除项（确认环境允许后再操作）。
3. 大文件尽量打包传输；成千上万个极小文件时，先压缩成一个包会明显更快。
4. 接收端磁盘空间至少预留“本次总量 + 1 GB”。

## 8. 数据、隐私与安全模型

### 端到端加密（设备互传）

- 每台设备有独立的 Ed25519 长期身份密钥，设备 ID 由公钥哈希派生。
- 每次连接生成临时 X25519 密钥，做 ECDH 协商，再用 HKDF-SHA256 派生双向会话密钥。
- 控制消息和文件分块全部使用 AES-256-GCM 加密并认证，序列号防重放，帧长度有上限。
- 握手阶段双方用长期私钥签名，会话建立后校验对方身份与公钥哈希是否一致。
- 首次配对显示 6 位 SAS 验证码，防止中间人。
- 传输时逐块 SHA-256 校验；抓包只能看到密文帧。
- 心跳每 10 秒一次，30 秒收不到任何数据即判定断线；任一端掉线时，另一端会立即收到“连接已断开”提示并把设备标为离线。

### 本地数据文件

| 文件 | 内容 | 注意 |
| --- | --- | --- |
| `identity.json` | Ed25519 私钥、设备名、创建时间 | 私钥材料，不要复制或分享；删除后身份与配对关系全部失效 |
| `trusted.json` | 已配对设备的 ID、名称、指纹、最近地址 | 删除条目等于解除信任 |
| `settings.json` | 全部设置，含访客链接令牌与访问码 | 含敏感信息，不要外传 |
| `history.json` | 最近 200 条传输记录 | 含文件路径与访客 IP |

LanLink 不收集遥测，不上传任何文件或元数据，不依赖互联网。

### 访客模式边界

访客上传没有端到端加密，也没有 HTTPS；文件以明文 HTTP 在局域网内传输。它适合“可信局域网 + 临时分享”，不适合公网或不可信网络。主机端会校验每个分块的 SHA-256，并限制路径穿越、文件数、大小、并发和空闲时间。

## 9. 常见问题

**两台电脑互相看不到**

1. 确认都打开了 LanLink，且处于同一网段（例如都是 192.168.1.x）。
2. 确认都开启了“局域网自动发现”。
3. 检查 Windows 防火墙是否允许专用网络，或临时关闭第三方防火墙测试。
4. 关闭 VPN、虚拟网卡或访客 Wi-Fi，再重试。
5. 仍不行就用“手动连接 IP”，填写对方 IP 和 TCP 端口。

**提示端口被占用**

- TCP 7411：自动尝试 7411–7416，仍失败则改用随机端口，不影响使用，可在设置页查看实际端口。
- 访客端口 7420：自动尝试 +10 个端口，全部失败会显示“端口已被占用”，换一个端口即可。
- GUI 端口 7410：server 模式会自动顺延最多 20 个端口。

**访客打不开链接或提示“链接已失效”**

- 确认访客上传仍处于“运行中”，链接未过期。
- 确认对方与主机在同一局域网，且主机防火墙放行访客端口。
- 链接包含随机令牌，令牌错误会直接拒绝；请复制完整链接，不要手工截断。
- 如果刚刚点过“更新链接”，旧链接已失效，请使用新链接和新访问码。

**访问码一直提示不正确**

- 访问码是 6 位数字，以主机面板显示的为准。
- 同一 IP 1 分钟内尝试超过 20 次会锁定 5 分钟；等待后重试，或在主机上“更新链接与访问码”。

**发送时提示“对方正忙”**

对方当前已有进行中的接收任务。等对方当前任务结束后再发，或先取消对方任务。

**传输中断后怎么办**

重新发送同一批文件即可。接收端会保留 `.lanlink-part` 与 `.lanlink-part.json`，只补传缺失分块。若超过“未完成分块保留时长”，这些临时数据不再用于续传（访客模式还会定期清理过期临时文件），需要从头传输。

**大文件传到一半失败**

- 检查接收磁盘剩余空间（需求为文件总大小 + 少量余量）。
- 检查网络是否切换（Wi-Fi 漫游、休眠、网卡重连）。
- 检查接收目录是否被杀毒软件锁定或文件被其他程序占用。

**历史记录里的“打开”按钮无效**

桌面版会先在资源管理器中定位文件；若路径是文件夹则直接打开，路径不存在时提示“文件或文件夹不存在”。开发实例（`node src/server.js` + 浏览器页面）由本机服务调用资源管理器/Finder，同样会在路径缺失时报错；Linux 下还需要系统安装 `xdg-open`。

**如何解除配对 / 重置身份**

当前界面没有“解除配对”按钮。需要时请先退出 LanLink，再编辑数据目录中的 `trusted.json`（删除对应条目）或 `identity.json`（重置身份，所有配对失效），操作前先备份。修改后重启程序。

## 10. 命令行与开发测试

### 服务端参数（仅开发用）

桌面版不通过命令行启动；以下参数只影响 `node src/server.js` 启动的开发实例（`dev:a` / `dev:b` / `bench` 均以此方式运行）。

```bash
node src/server.js [选项]
```

| 参数 | 说明 |
| --- | --- |
| `--data <目录>` | 数据目录，默认 `~/.lanlink` |
| `--ui-port <端口>` | GUI 监听端口，默认 7410，0 表示随机 |
| `--tcp-port <端口>` | 设备间传输端口，默认 7411 |
| `--discovery-port <端口>` | UDP 发现端口，默认 7412 |
| `--name <名称>` | 覆盖设备名称 |
| `--no-discovery` | 关闭局域网自动发现 |
| `--auto-trust` | 自动信任连接方，跳过验证码确认；仅用于开发/测试 |
| `--verbose` | 输出调试日志到 stderr |

### 测试与基准

```bash
npm test            # 集成测试：加密、配对、文件夹、归档、冲突、续传、抓包校验等
npm run test:guest  # 访客上传测试：登录、分块、配额、续传、轮换、关闭端口
npm run bench       # 本机回环性能基准（两个独立服务进程）
```

基准脚本可用环境变量调整：

```bash
BENCH_LABEL=my-run BENCH_SIZE_MB=1024 BENCH_SMALL_COUNT=5000 BENCH_SMALL_SIZE=4096 npm run bench
```

基准会临时写入 `dev/bench-*`，结束后自动清理。

## 11. 已知限制

- 访客模式是 HTTP 明文，仅适合可信局域网。
- 目前没有二维码、手机 App、开机自启、自动更新和安装包；桌面版通过 `npm start` 启动。
- 组播发现不跨路由器，跨网段请手动连接 IP。
- 同一 IP 的访客并发、总并发、空闲超时均为固定上限，界面暂不可调。
- 尚未提供可视化的“解除配对”入口，需按上文手工编辑信任文件。
